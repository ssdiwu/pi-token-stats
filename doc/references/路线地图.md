# 路线地图

> **历史文档**：这是 pi-token-stats 时代的路线图，已被 `doc/10-需求规格/PRD-pi-session-insights.md` 取代。保留作历史参考，当前实施以 PRD 为准。2026-07-20 从 `doc/30-路线图/` 移入 `doc/references/`，内容未改。

## 当前定位

`pi-token-stats` 当前定位是 **Pi session（会话）消耗统计入口**：

- 读取 `~/.pi/agent/sessions` 下的 JSONL（会话日志）
- 按时间范围聚合 token（令牌）与 cost（费用）
- 提供 `/tokens` slash command（斜杠命令）
- 提供 `token_stats` tool（工具）给 agent 调用

现状已经覆盖了「花了多少」的问题，但还没有覆盖「为什么会花这么多」「这些消耗集中在哪类项目/会话/工作流」「如何减少上下文噪声」这几类更上层的问题。

## 下一阶段方向

### 1. 更舒服的上下文降噪

目标不是接管所有上下文管理，而是围绕 Pi 现有 session 数据和工具链，补齐 **高噪声命令输出 / 大段工具结果** 的轻量减压能力。

可推进点：

- 基于现有 session 统计结果，识别高噪声会话：例如单场会话里 `bash` / `read` / 大段 toolResult（工具结果）占比过高。
- 在报告中标记「高噪声会话」与「高噪声项目」，帮助用户先看到上下文被哪里刷爆。
- 评估是否补一个轻量 companion（伴随）扩展或脚本，只做 noisy tool output（噪声工具输出）压缩建议，不直接引入重型上下文框架。
- 如果后续接入外部降噪扩展，优先选**局部能力插件**，不要一开始上接管型上下文系统。

### 2. 更适合个人工作流的会话搜索 / 项目画像

当前 `/tokens` 解决的是时间维度统计，还缺：

- 按项目看最近 7 天 / 30 天总消耗
- 按 session title（会话标题）看热点主题
- 按模型看某项目主要消耗落在哪些 provider/model
- 按工具看项目画像：例如 `bash-heavy`、`edit-heavy`、`research-heavy`

可推进点：

- 在 `token_stats` 之外补一个项目维度聚合接口，按 `cwd`（当前工作目录）汇总 session。
- 增加「高消耗项目排行榜」「高消耗会话排行榜」「模型分布」等报告视图。
- 给同一逻辑项目的多路径 session 做**正常聚合**（例如工作区迁移、目录重命名后的历史会话），但不把某个用户的本地路径约定写成产品规范。
- 允许把临时实验目录、原型目录、正式仓库拆成父项目 / 子项目两个层级，而不是强行合并成一个数字。

### 3. 针对 Pi session JSONL 数据结构定制的检索

现有通用上下文框架通常太大，且默认假设是「统一接管上下文」；`pi-token-stats` 更适合沿着 **Pi 自己的 session JSONL 结构** 往前长。

可推进点：

- 直接利用会话事件类型做检索，而不是把所有内容先抽平：
  - `session`
  - `session_info`
  - `model_change`
  - `message.user`
  - `message.assistant`
  - `toolCall`
  - `toolResult`
- 在查询层支持按以下维度过滤：
  - 时间范围
  - 项目 / 子项目
  - 模型
  - 工具名
  - 标题关键字
  - 首问关键字
- 优先做「结构化检索 + 聚合摘要」，再决定要不要上全文索引或知识库。
- 保持实现轻量：先从本地 JSONL 扫描与增量缓存开始，不提前引入重型数据库和接管式上下文层。

## 暂不做

以下方向目前不作为近期主线：

- 不把 `pi-token-stats` 扩成通用 agent memory platform（智能体记忆平台）
- 不在当前阶段引入重型、强侵入的上下文管理框架来接管 Pi 全局工作流
- 不把某个用户机器上的目录偏好（例如 `Documents` vs `Workspace`）固化成产品规则

## 判断标准

如果下一步推进这些方向，优先看三个信号：

1. **是否减少真实分析成本**：用户能更快定位高消耗项目 / 会话 / 工具，而不是只看到总 token。
2. **是否减少上下文噪声**：用户能更快发现哪些工作流在浪费上下文窗口。
3. **是否贴合 Pi 原生数据结构**：实现直接建立在 session JSONL 与现有工具协议之上，而不是额外引入一整套通用框架。
