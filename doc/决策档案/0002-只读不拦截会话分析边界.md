# ADR 0002: 只读不拦截的会话分析边界

## 状态

Accepted

## 背景

对照 context-mode（拦截工具调用 + sandbox + session continuity + 跨 15 平台），本项目（pi-session-insights）定位是 Pi 会话信息拓展。

关键立论（已用本机真实会话文件核验）：Pi 原生 session JSONL 已足够丰富（cwd / token / cost / toolName / isError / compaction.tokensBefore / 工作流 custom 事件 / 两端时间戳可算延迟），靠「读 JSONL」即可达到竞品靠 hook 拦截才能拿到的绝大部分分析深度。

context-mode 之所以要拦截，是因为它目标跨 15 平台通用，很多平台原生日志不开放或不记这些事件；Pi 不存在这个问题。

## 决策

- 只读 `~/.pi/agent/sessions/**/*.jsonl`，绝不修改会话文件。
- 绝不引入拦截层：PreToolUse 路由、工具拦截、sandbox 执行、session continuity 恢复均不做。
- 数字面板视图（量纲/项目/工具/错误/健康）纯算法不调 LLM；LLM 仅用于日报/天摘要生成。

## 后果

- 能力边界：git 提交追踪、decision 追踪、delegation 分析拿不到（Pi JSONL 不直接记录，需拦截才能拿）——这些维度明确不做。
- session continuity 不做：Pi 已有原生 compaction + `/session` + `/resume` + `ctx.sessionManager.getBranch()`。
- 优势：零侵入、不破坏 Pi 原生工作流、不付拦截税、隐私本地。

## 验证

`rg "PreToolUse|tool_call.*block:|sandbox|ctx_exec" src/ index.ts` 应无结果。
