# 经验笔记

> 回答"这事儿怎么做"，收可改的做法与避坑经验（活页）。门槛：解决一个坑时，如果换一个无上下文的 agent 来会重走一遍，就值得记。格式：现象 + 做法 + 证据。重复发生时在原条目追加证据，不新建条目。

## 先算完数据再开面板，用户面对的是无响应的等待盲区

**现象**：`/insights` 无参数时，面板在 session 扫描和日报缓存读取全部完成后才出现，扫描期间终端没有任何反馈，像命令没响应。

**做法**：只借「overlay 先挂载、数据后刷新」的状态机：`ctx.ui.custom(...)` 的 factory 同步返回面板组件，构造函数以 `void this.refresh()` 启动异步读取，首帧只渲染加载态；请求结束后 `tui.requestRender()`，同一个 overlay 切换为结果或错误。失败留在面板内，不让面板消失。非 TUI 分支（`-p` / JSON / RPC）保持独立的纯文本路径，不走这套状态机。

**证据**：`src/panel.ts` 加载态与关闭后不再重绘的生命周期保护；`tests/panel-loading.test.ts`；做法来源见 [02-pi-dusage即时加载面板参考.md](./references/02-pi-dusage即时加载面板参考.md)。

## 范围查询按「读完全部 JSONL 再过滤」做，多次叠加会把堆打满

**现象**：`/insights` 与 `/daily` 的范围查询把每个 session 文件整份读入内存后再筛时间范围；多个扫描请求并行时，全量 JSONL 叠加直接触发 Node.js OOM（内存耗尽）。

**做法**：先按文件修改时间筛候选，再逐行读取并只保留目标范围内的事件与必要 session 元数据；多个外部扫描请求串行化，避免并行全量读取。聚合层保持纯函数，不因这个约束去改统计口径。

**证据**：`src/session-scan.ts`；`tests/session-scan.test.ts`（按修改时间和事件范围过滤、并发扫描后保持文件顺序）；`CHANGELOG.md` 0.2.1「范围扫描内存峰值」。

## 日报从别的包迁入时，默认目录和入口语义要先钉死再写代码

**现象**：`pi-daily` 的日报能力迁入本项目时，三处口径互相打架：归档目录有人沿用 Obsidian vault、有人沿用固定 Documents 目录；日界文档对「凌晨是否从 05:00 起算」有歧义；日报入口挂在 `/insights` 的字符串前缀检测上，LLM 的 tool 入口根本到不了日报。先写实现再补文档，三处各写各的，缓存键、归档文件名和命令行为对不齐。

**做法**：迁移前先把三件事落成决策再动代码：归档目录与模型选择（ADR 0005）、默认日界（ADR 0004）、入口形态与覆盖确认（ADR 0007）。决策之间的修订用正文内加注或「后记」指向新 ADR，不回头改旧决策的原文结论。

**证据**：`doc/决策档案/0004`、`0005`、`0007`；`CHANGELOG.md` 0.2.0 独立 `/daily` 与归档覆盖策略。
